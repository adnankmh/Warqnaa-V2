# عقد R12 Competitive Arena

الإصدار: **0.7.0+240**  
القاعدة: **R11 Build 230**

## 1. عقد التوافق التراكمي

R12 إضافة فوق R11 ولا يحذف أي جزء من Social World أو Clubs 2.0 أو المشاهدة والإعادات والخصوصية. كما يحافظ على Commerce R10.1 وAsset Delivery R10 وR9/R9.1 ومحركات R8. بوابات CI تشغّل العقود `R8 → R9 → R9.1 → R10 → R10.1 → R11 → R12` في الخلفية وAndroid وiOS والويب.

## 2. السلطة الخادمية

- إنشاء غرف Ranked والبطولات يتم عبر `GameFactory` والخادم فقط.
- غرف Ranked لا تحتوي Bots، ولا تسمح للمضيف بالطرد، ولا تسمح بالمشاهدة أو الصوت.
- `CompetitiveRatingService` يستخرج النتيجة من حالة الغرفة المكتملة؛ لا يوجد حقل API لقبول فائز من العميل.
- كل مباراة تحمل `match_key` فريداً، وتمنع `rating_processed` إعادة تطبيق النتيجة.
- لكل لاعب حدث MMR غير قابل للتكرار لكل نطاق عبر مفتاح قاعدة بيانات فريد.
- تغييرات التصنيف تحفظ `before/after/delta/result/expected/K-factor` وسياق المراجعة.

## 3. Ranked وMMR

- حساب واحد يملك Queue نشطاً واحداً فقط.
- المطابقة تشترط اللعبة وعدد المقاعد والمنطقة وفارق MMR المقبول لكل الأطراف.
- نافذة البحث تبدأ ضيقة وتتوسع زمنياً حتى الحد الأقصى، وتفتح Cross-region بعد الانتظار المحدد.
- اللاعب الأقدم غير المتوافق لا يحجب مجموعة عادلة خلفه؛ يفحص Matchmaker كل مرشح كنقطة ارتكاز مع تحقق ثنائي الجانب.
- أي علاقة Block تمنع جمع اللاعبين في مباراة واحدة.
- MMR مزدوج: `overall` و`game:{key}`، مع Placement وSoft Reset وسقف/أرضية وعقوبة انسحاب.
- الانسحاب اليدوي يُسجل في حالة الغرفة ويؤثر في النتيجة الخادمية، مع بقاء المقعد مملوكاً للاعب الحقيقي وقابلاً لإعادة الاتصال؛ لا يستبدله Bot.

## 4. المواسم والترتيب والمكافآت

- موسم واحد نشط ضمن نافذته الزمنية، مع انتقال scheduled/active/completed/cancelled وتفعيل متسلسل تحت قفل يمنع سباق الإدارة والـScheduler.
- ثمانية Tiers: Bronze, Silver, Gold, Platinum, Diamond, Master, Grandmaster, Warqnaa Legend.
- Leaderboards تدعم العام، اللعبة، الدولة والنادي.
- الإغلاق النهائي يلتقط Standings، ثم ينشئ مطالبة جائزة واحدة لكل لاعب مؤهل أكمل Placement وTier.
- استلام الجائزة Transactional وIdempotent؛ التوكن وXP والشارة لا تُصرف مرتين.

## 5. البطولات

- الجدول يحمل schema ثابتة `r12_competitive_bracket_v1` وبذوراً حتمية وإصداراً ورقماً لكل Round/Match.
- السعة مشتقة رياضياً من المقاعد والمراحل، بما يشمل جداول 3 مقاعد؛ لا تبدأ البطولة بسعة لا يمكنها تكوين شجرة مكتملة.
- التسجيل يُقفل بعد بناء الجدول، ولا يمكن حذف Entry أثناء المنافسة.
- بعد إصدار أول غرفة يصبح الجدول غير قابل لإعادة البناء القسري؛ الاسترداد يتابع نفس النسخة ولا ينشئ مباريات مكررة.
- كل غرفة رسمية مرتبطة بـ`CompetitiveMatch` وتستخدم محرك اللعبة الخادمي نفسه.
- بعد اكتمال كل مباريات المرحلة، يكوّن الخادم المرحلة التالية من المتأهلين فقط.
- التعادل ينشئ مباراة حسم خادمية، والمباراة الملغاة بالنزاهة تُستبدل بغرفة جديدة مع حفظ سجل الاستبدال والتدقيق.
- بطولات Club/Country تتحقق من عضوية النادي أو الدولة ومن مفاتيح التحكم الإداري.
- `TournamentSettlementService` يعيد التحقق داخل معاملة مقفلة من الغرفة النهائية وهوية الأبطال والتسجيل وحالة `settlement_ready`، ثم يصرف مرة واحدة فقط عبر `paid_at`.

## 6. النزاهة والإدارة

- Anti-cheat severity 4+ ينقل المباراة إلى `review` بلا MMR أو تأهل أو جائزة.
- الموافقة أو الإلغاء يحتاجان مديراً بصلاحية `competitive`، وكل Mutation يسجل عبر `AdminAuditService`.
- التسوية اليدوية تنشئ مباراة صناعية موثقة وحدثين: العام واللعبة، ولا تعدّل الرقم بصمت.
- Admin Competitive على الويب وFlutter يدير المفاتيح، إنشاء المواسم وتفعيلها، تسوية MMR، طابور النزاهة، إنشاء البطولات والجداول.

## 7. التشغيل والاسترداد

الأمر `warqna:competitive-tick` يشغّل دورة المواسم، ينظف Queue، يعيد محاولة النتائج المكتملة غير المعالجة، ويسترد الجداول وينشئ لقطات ترتيب دورية. يعزل فشل المباراة الواحدة كي تستمر بقية الدورة، ويسجل المراجع المتعثرة ويعيد Exit Code فاشلاً للمراقبة. يجب تشغيل Laravel Scheduler كل دقيقة. يدعم الأمر `--dry-run` للفحص دون Mutation.
